## Discrete parameter sets

- `KEYBOARD_OPEN.keyboardHeight`: {150000, 300000} milli-px (150 / 300 CSS px).
- `SCROLL` (dx, dy): {(-100000, 0), (0, -100000), (0, 100000), (100000, 0)}.
- `DELAYED_VISUAL_PAN` (dx, dy): dx is 0 only; dy in {-300000, -100000, 100000, 300000}.
  dx is 0 only because visualWidth always equals layoutWidth (no pinch zoom,
  scale fixed at 1), so maxLeft is 0 and any non-zero dx pan is clamped to an
  applied dx of 0 — a geometrically inert branch that would only duplicate states.
- `KEYBOARD_CLOSE`, `VIEWPORT_SETTLED`: no parameters.

## Depth / node bounds

- Default limits (Schema `viewportshift.scenario/v1`, DEFAULT_LIMITS):
  maxDepth 8, maxNodes 10000.
- Each fixture may freeze tighter limits in its own `limits` block;
  the search never exceeds the scenario's maxDepth / maxNodes.
- `limitReached: "depth"` means the queue was exhausted within maxDepth;
  `limitReached: "nodes"` means the node budget was exhausted first.
  Either way the result is BOUNDED_NO_WITNESS — never a claim that the
  whole space is safe.

## Dedup rule

Dedup key = the full ViewportState canonical JSON (all 13 fields, fixed
key order, including eventClock, scrollX/scrollY and pendingPan). Two
states share a key only when identical in every field, so different
observable geometry can never be merged. This is deliberately
conservative: states differing only in clock/scroll/pendingPan are kept
as separate nodes (over-splitting costs nodes; merging would cost
correctness). Regression fixture: bfs-dedup-rv-sheet — two depth-3
states with different observable geometry (visibleRatio 0 vs 500)
share one naive numeric-field sum (3402300) but have different keys;
an independent enumeration counts 74 distinct states to depth 3 under
the full key vs only 34 under the naive sum, and the BFS visits all 74.

## Semantics notes

- Any-step semantics: the predicate is evaluated after every step, including
  the initial state and every prefix step; the first failing step is the hit.
  (S0 scenario verdicts use final-step semantics instead; that is a verdict
  rule, not the BFS rule — a transient open-close failure is a BFS witness.)
- A hit is status FAIL with the full witness: event sequence, first failing
  predicate(s), and the before/after state and metrics of every step.
- Out-of-model inputs fail closed as UNKNOWN (e.g. profile.scale != 1,
  unknown mode); structurally malformed inputs are INVALID.
